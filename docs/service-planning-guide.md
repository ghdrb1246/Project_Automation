# 서비스 기획 사용 가이드

## 구조와 각 항목 채우는 법

| 섹션 | 무엇을 쓰나 | 분량 가이드 |
|---|---|---|
| **핵심 기능** | 서비스의 핵심 기능 3~5개, 각각 한 줄 요약 | 기능명 + 1~2문장 설명. "왜 필요한지"가 아니라 "무엇을 하는 기능인지"에 집중 |
| **타겟층** | 실제 사용자 페르소나 | 나이대·상황·니즈가 드러나게 2~3개 (예: "대학생, 스터디 그룹을 자주 만드는데 일정 조율이 힘든 사람") |
| **문제 정의 → 문제요약** | 지금 사용자가 겪는 불편을 한 문단으로 | 추상적인 표현보다 구체적 상황 묘사 |
| **문제 정의 → 해결방안** | 이 서비스가 그 문제를 어떻게 푸는지 | 핵심 아이디어 한 문단 |
| **유사 서비스 분석** | 경쟁/유사 서비스 2~3개 | 서비스별로 "특징"과 "한계" 각각 2개씩 bullet |
| **차별점** | 유사 서비스 대비 우리 서비스만의 강점 | 표 형식: 차별점 / 기존 서비스 대비 기대 효과 |

## 주의할 점 — 기술 스택 표는 중복 관리하지 마세요

지금 `서비스 기획` 페이지와 별도의 `기술 스택` 페이지에 **똑같은 표가 두 번** 들어가 있습니다. 같은 정보가 여러 문서에 흩어져 있으면 한쪽만 업데이트되고 다른 쪽은 옛날 내용으로 남는 "산출물 불일치" 문제가 그대로 재현됩니다.

**추천**: 기술 스택 표는 `기술 스택` 페이지에만 두고, `서비스 기획` 페이지에서는 표를 삭제한 뒤 `/link to page`로 `기술 스택` 페이지 링크만 걸어두세요. 이러면 스택이 바뀌었을 때 한 곳만 고치면 됩니다.

## 작성 순서 추천

1. 문제 정의(문제요약 → 해결방안)를 먼저 씁니다 — 이게 명확해야 나머지가 자연스럽게 따라옵니다
2. 타겟층을 정합니다
3. 핵심 기능을 정리합니다 (타겟층의 니즈에서 바로 도출되어야 함)
4. 유사 서비스 분석 → 차별점 순으로 마무리합니다 (우리 기능을 정한 뒤에 비교해야 차별점이 명확해짐)
