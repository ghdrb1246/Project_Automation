# WBS 사용 가이드

## 1. WBS의 역할

WBS는 **"지금 우리 팀이 뭘, 누가, 언제까지 해야 하는지"를 한곳에서 보는 일정 관리 허브**입니다. 기획 문서·산출물이 "무엇을 만들지"를 정하는 곳이라면, WBS는 "언제까지, 누가"를 정하는 곳입니다.

## 2. 새 업무 항목을 만들 때 채우는 순서

1. **업무 항목**(제목): 무엇을 하는 작업인지 한 줄로 (예: "회원가입 API 구현")
2. **업무 영역**: 아래 표 기준으로 선택
3. **담당자**: 본인 지정
4. **우선순위**: P0(필수·긴급) / P1(중요) / P2(있으면 좋음)
5. **마일스톤**: 어느 스프린트/주차 목표인지 (예: S1)
6. **작업일정**: 시작일~마감일
7. **연결 문서**(BE/FE 작업인 경우만): 관련된 기능 명세서 페이지와 연결 — 이걸 채워야 자동 불일치 감지가 동작합니다

## 3. 업무 영역별 정의

| 업무 영역 | 역할 | 예시 |
|---|---|---|
| **BE** | 백엔드 개발 작업 | API 구현, DB 스키마 작업, 서버 로직, 인증 처리 |
| **FE** | 프론트엔드 개발 작업 | 화면 구현, 컴포넌트 개발, API 연동 |
| **Ops** | 배포·인프라 작업 | 배포 환경 설정, CI/CD 구성, 서버 세팅, 모니터링 |
| **개인 일정** | 프로젝트와 직접 관련 없는 개인 사정 | 개인 사유로 일정 조율이 필요한 항목 |
| **미팅** | 회의·발표 등 정해진 시간에 모이는 일정 | 정기 회의, 스프린트 리뷰, 발표 당일 세션 |
| **백로그** | 아직 착수 안 한/우선순위 낮은 작업 대기열 | "언젠가 해야 하는데 지금은 아닌" 작업 |

> **2학기 프로젝트 추천 추가 항목**
> - **DB**: DB 설계·마이그레이션 작업 (지금은 BE에 섞여있어 구분이 안 됨)
> - **문서화**: 기능 명세서/API 명세서/발표 자료 등 문서 산출물 자체를 만드는 작업
> - **BD**: 팀 초기 역할 분담(PM/BE/FE/BD) 중 BD 담당자의 작업을 넣을 곳이 없었음
>
> 발표 관련해서는 "발표 자료 제작"은 `문서화`, "발표 당일"은 `미팅`으로 나눠서 기록하는 걸 추천합니다.

## 4. 업무 항목 현황(상태) 값

| 상태 | 의미 |
|---|---|
| 대기 | 아직 시작 안 함 |
| 작업 중 | 진행 중 |
| BE 연동 대기 | FE 작업은 끝났는데 BE API가 아직 준비 안 돼서 대기 중 |
| 퍼블리싱 완료 | (FE) 화면 마크업/스타일 작업 완료, 기능 연동은 아직 |
| 배포 완료 | 개발 서버/스테이징에 배포됨 |
| 최종 완료 | 실제 반영 완료, 더 이상 손댈 것 없음 |

각 담당자는 본인 작업 상태가 바뀔 때마다 이 값을 갱신해주세요 — `daily-discord-report.yml`이 매일 아침 이 값을 기준으로 임박/지연 항목을 알려줍니다.

## 5. `동기화 여부` — 자동으로 뜨는 경고 이해하기

WBS의 `동기화 여부`가 `⚠️`로 바뀌면, 연결된 기능 명세서(또는 그 기능 명세서와 연결된 API 명세서)가 최근에 수정됐다는 뜻입니다. 이 경우:
1. `연결 문서`에 걸린 기능 명세서를 열어서 뭐가 바뀌었는지 확인
2. 필요하면 WBS의 작업 내용이나 일정을 그에 맞게 조정
3. 확인이 끝났으면 기능 명세서를 한 번 더 저장(가벼운 수정 후 되돌리기 등)해서 "확인 완료" 상태로 갱신

## 6. 자주 헷갈리는 부분 (FAQ)

**Q. BE 작업인데 지금 당장은 안 할 거면 백로그에 넣나요, BE에 넣나요?**
A. 백로그에 넣으세요. `업무 영역`은 "어떤 종류의 작업인가"이고 `백로그`는 그중에서도 "아직 안 하는 것"이라는 별도 축입니다. 착수 시점이 되면 그때 `BE`로 바꾸고 일정을 잡으세요.

**Q. 회의 준비(자료 정리)는 미팅인가요?**
A. 아니요, 회의 자체(시간 블록)만 `미팅`이고, 준비 작업은 그 작업의 성격에 맞는 영역(`문서화`, `BE` 등)에 넣으세요.

**Q. 연결 문서를 꼭 채워야 하나요?**
A. `업무 영역`이 `BE`/`FE`인 작업만 채우면 됩니다. `미팅`/`개인 일정`/`백로그`/`Ops`는 대응되는 기능 명세서가 없는 게 정상이라 비워둬도 됩니다 (자동화가 `-`로 표시하고 넘어갑니다).

**Q. Task ID는 어떻게 생기나요?**
A. `Task ID` 속성이 `ID`(Unique ID) 타입으로 되어 있어서, 새 업무 항목을 저장하는 순간 `WBS-1`, `WBS-2`… 순서로 자동 채번됩니다. 손으로 입력할 필요가 없습니다.
